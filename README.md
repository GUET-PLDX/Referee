# Referee

底盘侧 RoboMaster 2027 裁判系统串口解析器，依据高校系列赛通信协议
V1.0.0（2026-10-29）。沿用 `ParseData()`、`Publish()` 和现有 Topic，
把机器人、比赛和发射相关的有效数据发布为 `RobotGameRefereePack`。

摘要携带 `source_command_id`、`source_valid_mask`、`source_fresh_mask` 和
`referee_online`。只有 CRC 和官方固定长度均正确的支持命令会更新来源。
合法收包间隔超过 1000ms 才离线；UART 的短读等待不会被当作业务离线。
离线清空有效位并发布状态；空闲期间也维护各来源的新鲜度。来源时间戳使用
32 位毫秒时间，差值计算支持回绕。

接收复用 LibXR UART、CRC8/CRC16、时间和信号量，在原线程内保留最多 512
字节的流式缓冲。分块、粘包和错误帧均重新搜索帧头；半包超过 50ms 未续收时
丢弃，单次 UART 等待最多 10ms。错误长度或未知命令不会更新业务数据及在线时间。

`ExpectedPayloadSize()` 是支持命令的固定长度入口，`0x0301` 另校验 6 字节交互头、
最多 112 字节内容及已知子命令长度。2027 布局包括 7 字节 `0x0204`/`0x0206`、
6 字节 `0x0209`、8 字节 `0x0101`/`0x020E`、12 字节 `0x0303`、
48 字节 `0x0305`、300 字节 `0x0310`，以及 `0x0A01`～`0x0A06` 雷达数据。
可选收包可通过加锁快照 `GetReceivedData()` 读取，无需增加导航 Topic。
旧 `0x0205`、`0x0309`、`0x0F01`、`0x0F02` 的类型名称保留给既有代码，
不属于默认 2027 支持集合：收包拒绝，相关发送接口返回 `NOT_SUPPORT`。

## 发送与错误

所有发送接口复用 `SendFrame()`、LibXR 有界 MPMC 队列和原 Referee 线程。
`OK` 表示请求已入队，或哨兵意图已合并；UART 完成结果通过 `GetLastTxError()`
观察，队列拒绝计数通过 `GetTxAdmissionErrors()` 观察。参数、长度、无有效本机 ID、
不支持命令和队列满均返回错误；持锁期间不等待 UART。帧缓冲保持到异步写完成，
BUSY 和失败保留当前帧重试。

所有 `0x0301`（包括通用接口、UI 和自主决策）发送尝试至少相隔 34ms；
`0x0305` 至少相隔 200ms，`0x0310` 至少相隔 20ms，分别计算额度，不累积补发。
持续复活决策和普通队列交替获得发送机会。`0x0310` 仅在构造参数选择
921600 波特图传链路时允许发送，使用完整 300 字节内容；115200 链路返回 `STATE_ERR`。

## 哨兵决策

`SentryProtocol` 的回调和监控只提交或合并意图。姿态仅接受 1/2/3，默认 3；
0 和 4～6 返回错误且不覆盖此前命令。自动确认复活仅在机器人状态新鲜且死亡时发送，
存活或状态过期时撤销。UART 完成不作为业务成功证据。

首次有效 `0x020D` 建立累计弹量和远程购买次数基线；建立前购买请求返回 `STATE_ERR`。
`AddNeedBullet()` 接受正增量，累计上限 2047；远程弹药和回血每次只推进 +1，
收到新鲜反馈确认后才处理下一个积压请求，上限 15，溢出返回 `OUT_OF_RANGE`。
失败及未确认时保留相同意图；离线不清零计数。只有观察到比赛结束后进入准备阶段，
且裁判反馈三项计数均为零时，才重建新局基线。

## LibXR 2.0 静态装配

使用 xrobot 1.0.1 的 `module` / 有序 `args`；构造函数显式注入外设与服务，实例按依赖顺序创建。参数名和顺序以头文件中的构造函数为准，固件示例见 `User/RobotConfig/`。

保留 PLDX 控制、协议、超时与离线保护。 `OnMonitor()` 由生成的监控循环直接调用。

可选图传遥控：当前两板配置 `cmd: nullptr`。启用 BindCMD 后，接收路径仅缓存键鼠与时间戳，由 CMD 所属任务检查失联并提交独立的 `RC_INPUT_REFEREE` 输入槽，避免覆盖 DR16。停止请求保留至少一周期，长接收间隔先发布离线再恢复；不在 UART 或 OnMonitor 路径访问 CMD。
